# chatai — Telegram ИИ-ответчик + голос

Отдельный Python-проект: бот принимает вопросы и фотографии, обращается к выбранному API ИИ, формирует ответ и отдельный сценарий русской озвучки, затем отправляет текст, голосовое сообщение и MP3. По желанию копирует текст и аудио в закрытый канал-архив.

## Главное изменение: любой API для ИИ и голоса

Основная языковая модель и TTS-настройки независимы. У каждого провайдера можно задать собственные:

- Base URL и путь endpoint;
- API-ключ, имя заголовка авторизации и префикс токена;
- дополнительные HTTP-заголовки в виде JSON;
- модель и список резервных моделей;
- формат запроса, JSON-шаблон и путь к нужному полю ответа.

**Для API, совместимого с OpenAI Chat Completions / Audio Speech**, обычно достаточно указать Base URL, API key и модель. Если API использует собственный протокол, включи режим \`custom_json\`, задай JSON-шаблон запроса и путь к тексту/аудио в ответе. Нельзя автоматически гарантировать поддержку абсолютно любого HTTP API без описания его формата — но типичные различия теперь настраиваются через переменные, без правки Python-кода.

## Основные возможности

- История последних сообщений и команда /new.
- Текстовые сообщения и фотографии заданий.
- Основной ИИ API с fallback-моделями.
- Независимый TTS API с fallback-моделями.
- Сценарий речи с правилами чтения дробей, скобок, степеней, интегралов, геометрии, физических величин и программного кода.
- Генерация длинной речи по частям, сборка MP3 и конвертация в OGG/Opus для Telegram voice-note.
- Отправка MP3 как отдельного скачиваемого аудиофайла.
- Канал-архив, настройки голоса/скорости, ограничение пользователей по Telegram ID.
- Docker, локальный polling и webhook для Render.

## Настройка основной ИИ-модели

Ключевые переменные окружения:

| Переменная | Назначение |
|---|---|
| \`AI_API_KEY\` | ключ выбранного ИИ API |
| \`AI_API_BASE_URL\` | Base URL провайдера, например \`https://api.openai.com/v1\` |
| \`AI_API_PATH\` | путь до endpoint, по умолчанию \`/chat/completions\` |
| \`AI_MODEL\` | точный идентификатор модели |
| \`AI_FALLBACK_MODELS\` | запасные модели через запятую |
| \`AI_API_MODE\` | \`openai_chat\` или \`custom_json\` |
| \`AI_AUTH_HEADER\` | имя заголовка ключа, по умолчанию \`Authorization\` |
| \`AI_AUTH_PREFIX\` | префикс ключа, по умолчанию \`Bearer \` |
| \`AI_EXTRA_HEADERS_JSON\` | дополнительные заголовки JSON-объектом |
| \`AI_REQUEST_TEMPLATE_JSON\` | JSON-тело для режима \`custom_json\` |
| \`AI_RESPONSE_TEXT_PATH\` | путь к тексту результата внутри JSON |

### Вариант A: OpenAI-совместимый API

Пример значений (это пример конфигурации, не действующие ключи):

\`\`\`dotenv
AI_API_KEY=твой_ключ
AI_API_BASE_URL=https://api.openai.com/v1
AI_API_PATH=/chat/completions
AI_API_MODE=openai_chat
AI_MODEL=имя-модели-из-документации-провайдера
AI_AUTH_HEADER=Authorization
AI_AUTH_PREFIX=Bearer
AI_EXTRA_HEADERS_JSON={}
AI_RESPONSE_TEXT_PATH=choices.0.message.content
\`\`\`

Для другого совместимого сервиса меняется Base URL, ключ и имя модели. У некоторых провайдеров Base URL уже содержит endpoint: если \`AI_API_PATH\` совпадает с окончанием Base URL, путь не будет добавлен второй раз.

### Вариант B: API с собственным JSON-протоколом

Поставь \`AI_API_MODE=custom_json\`. JSON-шаблон позволяет формировать API-тело с такими подстановками:

- \`{{model}}\` — выбранная модель;
- \`{{messages}}\` — messages в OpenAI-формате, включая system;
- \`{{conversation}}\` — история + вопрос без system-сообщения;
- \`{{provider_conversation}}\` — история и пользовательское сообщение с изображением в base64-структуре, похожей на Anthropic;
- \`{{history}}\` — предыдущие сообщения;
- \`{{prompt}}\` — новый текстовый вопрос;
- \`{{user_content}}\` — новый вопрос, в том числе в OpenAI-формате с image_url;
- \`{{system_prompt}}\` — системные инструкции бота;
- \`{{max_tokens}}\`, \`{{temperature}}\` — настройки генерации;
- \`{{image}}\`, \`{{image_mime_type}}\`, \`{{image_base64}}\` — данные изображения для собственной структуры запроса.

Когда значение в JSON-шаблоне — ровно строка-плейсхолдер, вместо неё подставляется исходное значение: число остаётся числом, массив — массивом, объект — объектом. Например:

\`\`\`dotenv
AI_API_MODE=custom_json
AI_API_PATH=/your/provider/chat
AI_REQUEST_TEMPLATE_JSON={"model":"{{model}}","messages":"{{conversation}}","system":"{{system_prompt}}","max_tokens":"{{max_tokens}}","temperature":"{{temperature}}"}
AI_RESPONSE_TEXT_PATH=data.answer
\`\`\`

Пример выше — только образец: структура запроса и \`AI_RESPONSE_TEXT_PATH\` должны соответствовать документации именно твоего провайдера. Для авторизации нестандартным заголовком установи \`AI_AUTH_HEADER\` и \`AI_AUTH_PREFIX\`. Например, API с ключом без Bearer-префикса: \`AI_AUTH_HEADER=x-api-key\`, \`AI_AUTH_PREFIX=\`. Дополнительные заголовки задаются JSON-объектом \`AI_EXTRA_HEADERS_JSON\`.

Если у API иной способ передачи изображений или отдельные поля для system-инструкций, поправь JSON-шаблон под этот формат и используй плейсхолдеры \`provider_conversation\` / \`image_base64\`. Провайдеры с нестандартной авторизацией, подписью запроса, загрузкой файла отдельным запросом или специфическим потоковым протоколом могут потребовать отдельный адаптер.

## Настройка API голосового генератора (TTS)

Голосовой API настраивается полностью независимо от основного ИИ. Для него предусмотрены Base URL, endpoint, ключ, заголовки, модель, резервные модели, шаблон запроса и разные форматы ответа.

| Переменная | Назначение |
|---|---|
| \`TTS_API_KEY\` | ключ TTS; если пустой, используется \`AI_API_KEY\` |
| \`TTS_API_BASE_URL\` | Base URL TTS-сервиса |
| \`TTS_API_PATH\` | путь endpoint, по умолчанию \`/audio/speech\` |
| \`TTS_API_MODE\` | \`openai_speech\` или \`custom_json\` |
| \`TTS_MODEL\` | идентификатор TTS-модели |
| \`TTS_AUTH_HEADER\` / \`TTS_AUTH_PREFIX\` | авторизация TTS |
| \`TTS_EXTRA_HEADERS_JSON\` | дополнительные заголовки JSON-объектом |
| \`TTS_REQUEST_TEMPLATE_JSON\` | собственный JSON для \`custom_json\` |
| \`TTS_RESPONSE_MODE\` | \`raw_audio\`, \`json_base64\` или \`json_url\` |
| \`TTS_RESPONSE_AUDIO_PATH\` | JSON-путь к base64-аудио |
| \`TTS_RESPONSE_URL_PATH\` | JSON-путь к URL готового аудио |
| \`TTS_VOICE_FIELD\` | имя поля голоса; пустое значение не отправляет его |
| \`TTS_SPEED_FIELD\` | имя поля скорости; пустое значение не отправляет его |
| \`TTS_FORMAT_FIELD\` | поле формата аудио, обычно \`response_format\`; пустое отключает |
| \`TTS_AUDIO_FORMAT\` | формат на выходе API, по умолчанию \`mp3\` |

### Режимы TTS

**OpenAI-совместимый speech endpoint:**

\`\`\`dotenv
TTS_API_KEY=твой_ключ
TTS_API_BASE_URL=https://your-tts-provider.example/v1
TTS_API_PATH=/audio/speech
TTS_API_MODE=openai_speech
TTS_MODEL=точное-имя-tts-модели
TTS_AUTH_HEADER=Authorization
TTS_AUTH_PREFIX=Bearer
TTS_VOICE_FIELD=voice
TTS_SPEED_FIELD=speed
TTS_FORMAT_FIELD=response_format
TTS_AUDIO_FORMAT=mp3
TTS_RESPONSE_MODE=raw_audio
\`\`\`

**API с собственным JSON-запросом:** поставь \`TTS_API_MODE=custom_json\` и задай \`TTS_REQUEST_TEMPLATE_JSON\`. Поддерживаются подстановки \`{{model}}\`, \`{{input}}\` / \`{{text}}\`, \`{{voice}}\`, \`{{speed}}\`, \`{{response_format}}\` и \`{{output_format}}\`.

- \`raw_audio\`: endpoint возвращает готовые бинарные байты файла.
- \`json_base64\`: endpoint возвращает JSON со строкой Base64; путь к ней задаётся в \`TTS_RESPONSE_AUDIO_PATH\` (например, \`data.audio\`).
- \`json_url\`: endpoint возвращает JSON со ссылкой на готовый аудиофайл; путь задаётся в \`TTS_RESPONSE_URL_PATH\` (например, \`result.url\`). Ссылка должна быть абсолютной HTTP(S). Ключ API не пересылается на адрес скачивания.

Если TTS-провайдер не принимает голос, скорость или формат, установи соответствующее поле пустым. В режиме \`custom_json\` состав запроса полностью определяется шаблоном. Имена полей, допустимые голоса, тип содержимого ответа и тарификация зависят от провайдера — сверь их с документацией API.

## Русская речь для математики, физики и кода

ИИ создаёт два независимых представления ответа: HTML для Telegram и сценарий речи. Сценарий должен явно проговаривать группировку, скобки, числитель и знаменатель, степени, корни, интегралы и дифференциалы, геометрические обозначения, физические единицы и значимые знаки кода. Качество зависит от выбранной языковой модели и TTS; проверить его нужно на своих заданиях.

## Установка и запуск локально

Требуется Python 3.12+ и FFmpeg (нужен для конвертации MP3 в OGG/Opus).

1. Скопируй \`.env.example\` в \`.env\`.
2. Создай Telegram-бота через \`@BotFather\`, заполни \`TELEGRAM_BOT_TOKEN\`.
3. Запусти приложение, отправь \`/id\`, внеси числовой ID в \`ALLOWED_USER_IDS\` и перезапусти.
4. Укажи параметры API основной ИИ-модели и TTS.
5. Выполни:

\`\`\`bash
python -m venv .venv
pip install -r requirements.txt
python main.py
\`\`\`

Windows PowerShell: активируй окружение командой \`.venv\\Scripts\\Activate.ps1\` перед установкой пакетов. При пустом \`WEBHOOK_URL\` используется polling.

## Render

1. Создай Web Service из этого репозитория или используй Blueprint \`render.yaml\`.
2. В Environment задай токен Telegram, список разрешённых пользователей, Base URL, ключ и модель ИИ; отдельно настрой TTS Base URL, ключ и модель.
3. Render автоматически задаёт \`RENDER_EXTERNAL_URL\`, приложение регистрирует webhook.
4. Для архива создай закрытый канал и добавь бота администратором с правом публикации; затем укажи \`ARCHIVE_CHANNEL_ID\`.
5. Порт задаётся как `PORT=10000`; Docker запускает Uvicorn на `0.0.0.0:$PORT` и объявляет `EXPOSE 10000`. На Render не нужен ручной проброс портов: Render направляет HTTP-трафик на порт, который слушает приложение.

6. `/livez` — простая проверка, что HTTP-сервер отвечает. `/healthz` — проверка готовности: база, Telegram-транспорт, список разрешённых ID и настройки обоих API. При неполной конфигурации он вернёт HTTP 503 с перечнем проверок, чтобы Render не считал сервис полностью готовым. Путь `/healthz` настроен в Blueprint как health check.

Бесплатный Render может засыпать, а SQLite на временной файловой системе не сохраняет историю надёжно между перезапусками. Для постоянной истории требуется постоянный диск и правильный \`DATA_DIR\` / \`DATABASE_PATH\` или адаптация к внешней БД. Уже опубликованные аудиофайлы в Telegram-канале сохраняются.

## Команды бота

- \`/start\`, \`/help\` — справка;
- \`/new\` — очистить историю;
- \`/voice имя\` — выбрать голос, если TTS API поддерживает поле голоса;
- \`/speed 1.1\` — настройка скорости, если TTS API поддерживает поле скорости;
- \`/settings\` — текущие настройки;
- \`/id\` — Telegram ID.

## Безопасность

- Никогда не коммить настоящий \`.env\` и API-ключи.
- Не оставляй \`ALLOWED_USER_IDS\` пустым в публичном боте.
- Не помещай пользовательские значения в заголовки или JSON-шаблоны без проверки.
- Убедись в доступности выбранной модели, тарифе и лимитах API до активного использования.
